# 可恢复后台导入任务 — 风险清单

依据：`project/feature-brief.md`、`project/architecture.md`、`project/constraints.md`

| 风险 | 影响 | 缓解 | 验证方式 |
|---|---|---|---|
| Runtime Event 被当作最终业务状态（如进度落库、UI 直接写状态） | 违反架构约束；重启后结果不可信 | 明确事件仅含瞬时字段（percent、processedRows）；最终事实一律经 Product Owner 写库；执行期间禁止写库路径 | 代码审查 + B2 集成测试断言事件不更新任何最终状态字段 + A1 测试断言执行期间无进度写库 |
| 取消非幂等（重复取消报错或产生副作用） | 用户操作失败、状态错乱 | 状态机在终态直接返回成功；取消处理加锁/原子状态迁移 | A2 单元测试覆盖终态重复取消、运行中取消、并发取消 |
| 崩溃/重启后任务状态丢失或恢复失败 | 用户无法查看最终结果，违背核心目标 | 任务事实持久化到数据库；启动时由 Product Owner 恢复并重调度中断任务 | A1 持久化单测 + D1 崩溃恢复测试（模拟崩溃后重启） |
| 启动恢复策略遗漏或歧义（running 任务恢复重跑 vs 标记 failed 未定义） | 重启后任务状态不确定，用户无法查看结果 | 启动恢复作为显式任务 D1，明确默认策略：将中断的 running 任务标记为 failed，失败不阻断启动 | D1 测试按文档化策略断言 + 范围核对 |
| 进度推送过频导致 UI 卡顿或主进程负担 | 性能问题、体验下降 | 节流/合并瞬时进度事件；事件仅用于展示 | B1 集成测试 + 性能冒烟检查 |
| 取消后任务仍在后台写库（竞态） | 状态不一致，终态被覆盖 | 执行器先检查取消标志再落终态；终态写入为原子操作 | B1 集成测试覆盖取消竞态场景 |
| Renderer 绕过 IPC Contract 直接访问状态 | 分层架构被破坏，难以维护 | 契约测试强制渲染层只经 IPC；代码审查把关 | C1 契约测试断言渲染层仅依赖 IPC 通道 |
| 失败任务阻断应用启动 | 应用不可用 | 启动恢复逻辑捕获所有任务异常，失败任务标记为 failed 而非抛错阻塞 | D1 测试：注入失败任务后应用仍正常启动 |
| 任务结果超过存储限制或含敏感数据 | 存储膨胀、安全问题 | 结果字段限长/裁剪；敏感信息脱敏后入库 | 代码审查 + A1 仓储测试 |
| 范围蔓延（云同步、打包等非本次范围） | 交付延期 | 以 constraints.md 为准，验收不包含打包，不实现云同步 | D2 端到端验收清单核对范围 |
